2. 되돌아가는 길 — 시나리오 9개가 전부 여기다

대부분의 Flow Diagram 은 왼쪽에서 오른쪽으로만 흐릅니다. 아래 6개 화살표를 그려 넣어야 9개 시나리오가 그림 위에서 설명됩니다.

↩ A · 조건 다시 [장소 검색] ➔ 되돌아 ➔ [조건 입력]
조건을 거는 것뿐 아니라 푸는 길도 있어야 함 — 시나리오 1, 3
↩ B · 장소 다시 [예약] ➔ 되돌아 ➔ [장소 검색]
이미 예약한 뒤에 다른 곳으로 — 시나리오 2
↩ C · 이월 갱신 ★ [장소 다시 예약] ➔ [택시 도착지] 를 덮어씀
이 화살표가 이 과제의 핵심 — 시나리오 7. 장소를 바꾸면 택시 도착지가 따라가는가? 정답이 없음
↩ D · 슬롯 수정 [확정] ➔ 되돌아 ➔ [출발지·시간·차종]
배차가 끝난 뒤에도 고칠 수 있어야 함 — 시나리오 4, 5, 6
↩ E · 차종 ➔ 재배차 [차종 변경] ➔ [기사 매칭] 다시
차종을 바꾸면 기사가 자동으로 다시 잡힘 — 시나리오 5
↩ F · 전체 초기화 [어디서든] ➔ [도메인 고름] · 옛 호출은 취소 로
시나리오 9

3. 두 방식이 갈리는 곳 — 같은 창고, 다른 입구

웹 · 폼칸을 채운다
↘
Supabase
↙
봇 · 대화말로 한다

웹은 수정 입구가 둘 — ① 확정 카드에서 줄마다 [수정] (장바구니식) ② 위쪽 폼을 고치고 [변경 저장] (일괄식)
봇은 입구가 하나 — 말 한 문장. 대신 여러 칸을 한 번에 바꿀 수 있고 “거기로 가는 택시” 처럼 이름을 안 말해도 알아들음

4. 손으로 그릴 때 순서

  1. 2번 섹션의 큰 줄기를 가로로 한 줄 그린다 (상자 9개)
  2. 아래에 Supabase 원통 하나, 점선으로 연결
  3. ★ 이월 상자를 눈에 띄게 (다른 색 / 두꺼운 테두리)
  4. 위쪽에 빨간 되돌아가는 화살표 6개 (A~F). 이게 진짜 볼거리
  5. 왼쪽에 웹 · 봇 두 입구를 그리고 창고로 모은다
  6. C 화살표 옆에 한 줄 적는다 — “장소를 바꾸면 도착지도 따라간다”
